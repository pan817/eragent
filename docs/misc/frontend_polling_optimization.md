# 前端轮询优化要求

## 问题描述

后台日志发现前端在用户无操作时仍高频轮询会话列表和会话详情，每组 3 个请求（`/sessions?limit=50` × 2 + `/sessions/{id}` × 1），间隔约 15-30 秒，持续超过 14 小时，累计 200+ 次无效请求。

## 日志证据

```
INFO: 127.0.0.1:60110 - "GET /api/v1/ptp-agent/sessions?limit=50 HTTP/1.1" 200 OK
INFO: 127.0.0.1:60112 - "GET /api/v1/ptp-agent/sessions?limit=50 HTTP/1.1" 200 OK
INFO: 127.0.0.1:60114 - "GET /api/v1/ptp-agent/sessions/d2fd4edc-... HTTP/1.1" 200 OK
（每 15-30 秒重复，从 23:50 持续到次日 14:11）
```

## 优化要求

### 1. 增加 idle 检测

- 用户无操作（无鼠标移动、无键盘输入、无滚动）超过 **2 分钟**后，停止或大幅降低轮询频率
- 用户恢复操作时立即恢复正常轮询

### 2. 轮询退避策略

| 状态 | 轮询间隔 |
|------|---------|
| 用户活跃 + 有分析任务运行中 | 3 秒 |
| 用户活跃 + 无任务运行 | 30 秒 |
| 用户空闲（2 分钟无操作） | 停止轮询 |
| 页面不可见（`visibilitychange`） | 停止轮询 |

### 3. 避免重复请求

- 当前每次轮询发送 2 个相同的 `/sessions?limit=50` 请求，应合并为 1 个
- 如果会话列表未变化（可通过 ETag 或内容 hash 判断），跳过会话详情请求

### 4. 使用 SSE 替代轮询（推荐）

分析任务已支持 SSE 事件流（`GET /analyze/tasks/{trace_id}/events`），前端应：
- 分析进行中时使用 SSE 订阅实时事件，不轮询
- 仅在需要刷新会话列表时才发起 REST 请求

### 5. 页面关闭/切换时清理

- `beforeunload` 或 `visibilitychange` 事件触发时，取消所有进行中的轮询定时器
- 避免后台标签页持续占用服务器资源
