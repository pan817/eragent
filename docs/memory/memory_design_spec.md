# 设计目标
要为当前agent设计一套合理的memory管理体系，要权衡记忆内容的正确性，成本合理，可维护性高，具备足够韧性，而且符合erp agent的定位


# 设计重点
1. 要确认记忆内容是正确
2. 维护记忆的架构和代码成本是合理的
3. 记忆要成体系，要依据erp agent的业务背景，明确记忆内容的类型，记忆形态（短期和长期）的协同方案
4. 要考虑可维护性，记忆的入口要抽象，实现逻辑要内聚，和其他逻辑模块解耦，要实现记忆维护的全链路监控（和analyze接口独立的监控）
5. 要具备足够韧性，考虑最坏情况下，也能维持最基本的正常工作
6. 要符合erp agent的业务背景，做适当的优化，比如entity的记忆，指代消除等
7. 合理的技术架构，这个agent是服务端部署，记忆不能依赖md等文件体系，要使用pg数据库，向量数据库等外部存储
8. 合理的记忆生命周期，记忆不能不存活，也不能长期存活，维护记忆的成本会非常高
9. 合理的压缩策略
10. 性能响应，当前agent是erp agent，会和用户实时交互，性能体验也非常重要


# 不考虑的点
1. 当前不考虑多agent的模式，但要预留扩展性，未来一定会演进为多agent模式
2. 不考虑团队记忆，以后也没有
