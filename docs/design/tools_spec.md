# tools工具的架构设计方案

## 背景
当前系统有2套查询erp业务数据等工具，一套是基于pg查询，一套是基于graphiti的图数据查询工具。当前设计的思路，基于我们既定的业务场景和兜底的react场景，提供了两套实现。根据开关配置的情况，决策执行llm的时候，注入pg查询工具，还是图的查询工具。但是这样在架构上有问题，pg的查询能力和基于graphiti的查询能力不一致，表现在graphiti的查询能力在pg里不一定有，而且基于pg实现的工具可能未有利用图的关联查询，相当于削弱了图查询能力。

## 目标
基于pg查询，基于graphiti的图查询方案，分别实现一套适合自己的查询工具，不追求等级的双实现，但要最终满足erp agent的各项查询和分析能力。


## 步骤
1. 可以读一下claude.md文件，了解项目的背景
2. 可以读一下docs/etl下的graphiti的实现
3. 可以读一下当前tools的实现，另外一个会话当前正在实现等价的graphiti的工具实现
4. 分析当前需求的合理性
5. 分析当前需求的可行性
6. 给出实现方案
